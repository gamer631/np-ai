# NILcenter.ai Laboratory Catalog

The catalog defines the research domains that the operating system will integrate. A laboratory is a curated environment containing tools, datasets, workflows, documentation and reproducible experiments.

The long-term product target is **100+ validated modules per mature laboratory**. This is a capacity target, not a claim that those modules already exist. Modules must be useful, distinct, maintained, licensed correctly and tested before publication.

## Initial laboratory divisions

| ID | Laboratory | Scope |
|---|---|---|
| `cybersecurity` | Cybersecurity & Defensive Testing | Authorized assessment, secure configuration, vulnerability validation, digital forensics and isolated training ranges |
| `reverse-engineering` | Reverse Engineering | Static analysis, debugging, disassembly, file-format inspection and malware analysis in isolated environments |
| `ai-ml` | AI & Machine Learning | Model development, inference, evaluation, datasets, agents and reproducible training |
| `software-engineering` | Software Engineering | IDEs, compilers, build systems, debugging, code quality, testing and release engineering |
| `network-research` | Network & Protocol Research | Protocol inspection, packet analysis, network diagnostics and lab-only traffic generation |
| `hardware-electronics` | Hardware & Electronics | Circuit design, microcontrollers, firmware, logic analysis and hardware debugging |
| `robotics` | Robotics & Automation | Robot simulation, control systems, ROS integrations and safe automation |
| `cloud-infrastructure` | Cloud & Infrastructure | Containers, infrastructure-as-code, observability and authorized cloud configuration testing |
| `data-science` | Data Science & Analytics | Data cleaning, statistical analysis, visualization and reproducible pipelines |
| `scientific-computing` | Scientific Computing | Mathematics, physics, chemistry, numerical methods and scientific visualization |
| `quantum-computing` | Quantum Computing | Quantum circuit design, simulators and algorithm experiments |
| `innovation-prototyping` | Innovation & Prototyping | Rapid prototypes, experiment tracking, hardware/software proof-of-concepts and project evaluation |

## Expansion candidates

Agriculture technology, renewable energy, climate science, materials science, geospatial research, space science, biotechnology and assistive technology can become dedicated laboratories after demand, safety, licensing and maintainer capacity are demonstrated.

## Module maturity levels

1. **Proposed:** reviewed idea; not installable.
2. **Experimental:** installable in a disposable workspace; limitations clearly shown.
3. **Validated:** tests, documentation, license review and reproducible result.
4. **Maintained:** security updates, compatibility policy, owner and release process.
5. **Trusted:** signed release, independent review for high-risk capabilities and published provenance.

## Cybersecurity policy

Cybersecurity tools are designed for systems the operator owns or is explicitly authorized to assess. High-risk testing belongs in isolated ranges with scoped targets and explicit approvals. Credential theft, stealth, persistence, destructive actions and unauthorized access are not product goals.
